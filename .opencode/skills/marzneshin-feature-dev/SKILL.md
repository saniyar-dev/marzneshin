# Marzneshin Backend Feature Development

Marzneshin is a FastAPI backend with a deliberately flat architecture — **routes call `crud.*` directly**, there is no service layer, ORM models live in a single file, and Pydantic schemas are split into Base / Create / Modify / Response. Follow the existing conventions exactly; deviations create drift.

## When to Apply

Load this skill when the user asks to:
- Add a new resource (e.g., "add a `Plan` entity", "let admins manage X")
- Add or modify an API endpoint in `app/routes/`
- Create or alter Pydantic schemas in `app/models/`
- Add or alter SQLAlchemy models / Alembic migrations in `app/db/`
- Add or modify a CLI command under `cli/`
- Add a background task under `app/tasks/`
- Wire a side effect (marznode push, notification) to an existing route
- Extend the notification system (`app/notification/`, `app/models/notification.py`)

Do NOT load this skill for dashboard/ (React/TS) work.

## Architecture at a Glance

| Layer | Location | Responsibility |
|---|---|---|
| FastAPI app + lifespan + scheduler | `app/marzneshin.py:52-79` | App factory, CORS, mount static, exception handler |
| Routers (HTTP boundary) | `app/routes/*.py` | Endpoints, response_model, exceptions, auth deps, logging |
| Pydantic schemas (DTOs) | `app/models/*.py` | Request/response shapes, validation, computed fields |
| ORM models | `app/db/models.py` (single file) | All SQLAlchemy tables, association tables, hybrid properties |
| CRUD (pure DB) | `app/db/crud.py` (single file) | Top-level functions, no HTTP knowledge |
| DB session | `app/db/__init__.py:30-41` | `GetDB` context manager + `__all__` re-exports |
| Dependencies / auth | `app/dependencies.py` | `get_db`, `get_current_admin`, `sudo_admin`, type aliases |
| Side effects | `app/marznode/operations.py`, `app/notification/notifiers.py` | Marznode push, Telegram/webhook notifications |
| Background tasks | `app/tasks/*.py` | APScheduler jobs registered in `app/marzneshin.py:80-106` |
| CLI | `cli/*.py` + `marzneshin-cli.py` | Typer subcommands, reuse `app.db.crud` + schemas |
| Migrations | `app/db/migrations/versions/` | Alembic, autogenerated, edited manually after |

Key type aliases (use everywhere instead of writing `Depends(...)` inline):
```python
# app/dependencies.py:123-131
DBDep = Annotated[Session, Depends(get_db)]
AdminDep = Annotated[Admin, Depends(get_current_admin)]
SudoAdminDep = Annotated[Admin, Depends(sudo_admin)]
UserDep = Annotated[User, Depends(get_user)]
ServiceDep = Annotated[Service, Depends(get_service)]
```

## Adding a New Resource (canonical workflow)

Reference implementations: `Service` (simplest) and `User` (most complex with side effects).

### 1. Plan first

Before touching code, decide:
- **Table name** — plural snake_case (`widgets`)
- **Schema split** — always Base / Create / Modify / Response
- **Auth scope** — admin-only? sudo-only? per-admin scoping?
- **Side effects** — marznode push? notification? what action enum?
- **Pagination** — every list endpoint returns `Page[T]`
- **Soft vs hard delete** — see how `User.removed` works (`app/db/models.py:261`)

### 2. Create the Alembic migration

```bash
alembic revision --autogenerate -m "add widgets table"
```

Edit the generated file in `app/db/migrations/versions/`. Always:
- Add `op.create_index(...)` for any field you filter on
- Add `server_default=` on booleans/timestamps so SQLite and Postgres match
- Reference: `app/db/migrations/versions/20240115_20faa9f18c0a_init.py` for seed-data + cert-gen pattern

### 3. Add the SQLAlchemy model

**Append to `app/db/models.py` — do NOT create a new file.** Reference: `Admin` at `app/db/models.py:72-124`.

```python
class Widget(Base):
    __tablename__ = "widgets"
    id = Column(Integer, primary_key=True)
    name = Column(String(64), unique=True, index=True, nullable=False)
    enabled = Column(
        Boolean, nullable=False, default=True,
        server_default=sqlalchemy.sql.true(),
    )
    created_at = Column(DateTime, default=datetime.utcnow)
```

For many-to-many, declare the association `Table(...)` at the top of the file next to the existing ones (`app/db/models.py:43-69`).

### 4. Add Pydantic schemas

Create `app/models/widget.py`. Reference: `app/models/service.py` (simplest), `app/models/admin.py` (auth pattern), `app/models/user.py` (cross-field validators).

```python
from pydantic import BaseModel, ConfigDict, Field


class WidgetBase(BaseModel):
    name: str
    model_config = ConfigDict(from_attributes=True)


class WidgetCreate(WidgetBase):
    model_config = ConfigDict(
        json_schema_extra={"example": {"name": "my-widget"}}
    )


class WidgetModify(WidgetBase):
    name: str | None = None


class WidgetResponse(WidgetBase):
    id: int
```

Password / hash pattern: see `AdminCreate` at `app/models/admin.py:29-35` — expose a `@property hashed_password` so routes pass the schema straight into `crud.create_admin(...)`.

### 5. Add CRUD functions

**Append to `app/db/crud.py` — do NOT create a new file.** Pattern:

```python
def create_widget(db: Session, widget: WidgetCreate) -> Widget:
    dbwidget = Widget(name=widget.name)
    db.add(dbwidget)
    db.commit()
    db.refresh(dbwidget)
    return dbwidget


def get_widget(db: Session, id: int) -> Widget | None:
    return db.query(Widget).filter(Widget.id == id).first()


def get_widgets(db: Session, name: str | None = None) -> list[Widget]:
    query = db.query(Widget)
    if name:
        query = query.filter(Widget.name.ilike(f"%{name}%"))
    return query.all()


def update_widget(db: Session, dbwidget: Widget, modification: WidgetModify) -> Widget:
    if modification.name is not None:
        dbwidget.name = modification.name
    db.commit()
    db.refresh(dbwidget)
    return dbwidget


def remove_widget(db: Session, dbwidget: Widget) -> None:
    db.delete(dbwidget)
    db.commit()
```

Then **add the new functions to `app/db/__init__.py`** in both the `from .crud import (...)` block and the `__all__` list.

### 6. Add the route file

Create `app/routes/widget.py`. Reference: `app/routes/service.py` (full file, the cleanest pattern).

```python
import logging
import sqlalchemy

from fastapi import APIRouter, HTTPException, Query
from fastapi_pagination import Page
from fastapi_pagination.ext.sqlalchemy import paginate

from app.db import crud
from app.db.models import Widget
from app.dependencies import DBDep, AdminDep, SudoAdminDep, WidgetDep
from app.models.widget import (
    WidgetCreate, WidgetModify, WidgetResponse,
)

logger = logging.getLogger(__name__)

router = APIRouter(prefix="/widgets", tags=["Widget"])


@router.get("", response_model=Page[WidgetResponse])
def get_widgets(db: DBDep, admin: AdminDep, name: str = Query(None)):
    query = db.query(Widget)
    if name:
        query = query.filter(Widget.name.ilike(f"%{name}%"))
    if not admin.is_sudo:
        query = query.filter(Widget.id.in_(admin.widget_ids))
    return paginate(query)


@router.post("", response_model=WidgetResponse)
def add_widget(new_widget: WidgetCreate, db: DBDep, admin: SudoAdminDep):
    try:
        dbwidget = crud.create_widget(db, new_widget)
    except sqlalchemy.exc.IntegrityError:
        db.rollback()
        raise HTTPException(
            status_code=409, detail="Widget by this name already exists"
        )
    logger.info("Widget `%s` added", dbwidget.name)
    return dbwidget


@router.get("/{id}", response_model=WidgetResponse)
def get_widget(widget: WidgetDep, admin: AdminDep):
    return widget


@router.put("/{id}", response_model=WidgetResponse)
def modify_widget(
    modification: WidgetModify, widget: WidgetDep, db: DBDep, admin: SudoAdminDep,
):
    return crud.update_widget(db, widget, modification)


@router.delete("/{id}")
def remove_widget(widget: WidgetDep, db: DBDep, admin: SudoAdminDep):
    crud.remove_widget(db, widget)
    return dict()
```

### 7. Add the row-as-dependency (optional but recommended)

In `app/dependencies.py`, alongside `get_service` at line 116:

```python
def get_widget(id: int, db: DBDep) -> Widget:
    widget = crud.get_widget(db, id)
    if not widget:
        raise HTTPException(status_code=404, detail="Widget not found")
    return widget


WidgetDep = Annotated[Widget, Depends(get_widget)]
```

### 8. Register the router

Edit `app/routes/__init__.py`:

```python
from . import admin, node, service, inbounds, subscription, system, user, widget

api_router.include_router(widget.router, prefix="/api")
```

**Never omit `prefix="/api"`** unless the endpoint is intentionally public (only `subscription.router` does this — see Anti-pattern #3).

### 9. (Optional) Add CLI commands

Create `cli/widget.py` with a Typer subapp. Reuse the **same** CRUD functions and the **same** Pydantic schemas as the route — never duplicate validation logic. Reference: `cli/admin.py`. Register in `marzneshin-cli.py:13-15`:

```python
app.add_typer(cli.widget.app, name="widget")
```

### 10. (Optional) Add a notification action

If the feature fires user-facing notifications, add an enum entry to `app/models/notification.py:22-33` (`UserNotification.Action`) and a subclass at `app/models/notification.py:36-90`. Then fire from the route via:

```python
asyncio.ensure_future(notify(
    action=UserNotification.Action.widget_created,
    user=user_response, by=admin,
))
```

### 11. (Optional) Add a background task

Create `app/tasks/widget_sweep.py`. Register in `app/marzneshin.py:80-106` and import it there. Use `with GetDB() as db:` (not `Depends`). Reference: `app/tasks/expire_days_reached.py:30-43`.

## Extending an Existing Resource

- **New column on `User`/`Admin`/`Service`/`Node`** → add Alembic migration, extend the ORM model in `app/db/models.py`, extend the relevant Pydantic schema in `app/models/*.py`, extend CRUD in `app/db/crud.py`, then add a re-export to `app/db/__init__.py`.
- **New endpoint on existing router** → edit the existing `app/routes/<feature>.py`, follow the same patterns.
- **New filter param on a list endpoint** → add a `Query(None)` arg, branch on it before `paginate()`. Use the existing `user_filters` pattern only when you have 5+ filters (`app/routes/user.py:46-54`) — explicit `if` branches are preferred otherwise.
- **New notification action for an existing event** → add to `UserNotification.Action` enum + subclass, fire via `asyncio.ensure_future(notify(...))`.

## Anti-Patterns (DO NOT)

| # | Smell | Why | Reference |
|---|---|---|---|
| 1 | Two competing update functions for the same entity | Confuses callers; pick one. Currently `update_admin` vs `partial_update_admin` coexist | `app/db/crud.py:800-840` |
| 2 | Adding a new router but forgetting to register it in `app/routes/__init__.py` | Endpoint is silently unreachable | `app/routes/__init__.py` |
| 3 | Public/auth-less endpoint under `/api/...` | `/api` is the admin-auth scope; only `subscription.router` is intentionally prefix-less | `app/routes/__init__.py:11` |
| 4 | `User.removed == False` (or any `Column == False`) in queries | Breaks on NULL rows; use `~User.removed` | `app/db/crud.py:381, 587` vs `app/db/models.py:261` |
| 5 | Bare `except:` blocks | Swallows `KeyboardInterrupt`/`SystemExit`; use `except Exception:` | `app/tasks/record_user_usages.py:125`; `app/marznode/grpclib.py:89`; `app/marznode/grpcio.py:178` |
| 6 | Splitting ORM models across multiple files | Project convention is one file; deviations break import order and circular deps | whole codebase |
| 7 | Splitting CRUD across multiple files | Same — single-file convention | whole codebase |
| 8 | Adding a service layer between routes and CRUD | There is none; routes call `crud.*` directly | whole codebase |
| 9 | Using Pydantic v1 `Model.from_orm(...)` | Pydantic v2 dropped it; use `Model.model_validate(orm)` | `cli/subscription.py:32, 65` |
| 10 | Mixing Pydantic schemas with ORM models in API responses | DTOs should be pure Pydantic; convert at the boundary | routes vs `app/db/models.py` |
| 11 | `async def` on a route that only reads/writes the DB | Adds complexity, no benefit — sync is fine | `app/routes/service.py` (sync throughout) |
| 12 | Awaiting `notify(...)` inside a request handler | Use `asyncio.ensure_future(notify(...))` for fire-and-forget | `app/notification/notifiers.py` |
| 13 | Building a custom exception hierarchy | Use `HTTPException` directly; no `app/exceptions.py` exists | whole codebase |
| 14 | Building custom `@decorator`s for auth | Use FastAPI dependency functions instead | `app/dependencies.py:18-58` |
| 15 | Docstrings on every function | Codebase has minimal docstrings; only add when explaining non-obvious logic | whole codebase |
| 16 | Adding tests in random locations | Tests live under `tests/` at repo root (currently only `tests/test_migrations.py`) | `tests/` |
| 17 | Importing CRUD helpers without re-exporting them from `app/db/__init__.py` | Other modules import via `from app.db import crud` | `app/db/__init__.py` |
| 18 | Filter loops via `if name in locals()` for fewer than 5 filters | Hard to maintain; prefer explicit `if` branches or a typed filter schema | `app/routes/user.py:46-54` |
| 19 | CLI commands redefining validation rules instead of reusing route schemas | Causes drift; reuse `app/models/*.py` directly | `cli/admin.py` (correct pattern) |
| 20 | Editing the DB schema directly without an Alembic migration | All schema changes MUST go through Alembic; CI runs migrations matrix | `app/db/migrations/versions/`; `.github/workflows/migration.yml` |
| 21 | Hardcoding secrets in `app/config/env.py` | Always read from env via `python-decouple` | `app/config/env.py` |
| 22 | Returning raw ORM objects from a route | Convert via `Response.model_validate(obj)` first | `app/routes/user.py:138` |
| 23 | Using `Optional[X]` instead of `X \| None` | Project uses PEP 604 unions throughout | all of `app/models/*.py` |
| 24 | Adding a webhook handler without updating `app/webhooks.py` | Webhooks mount on a separate router | `app/webhooks.py` |
| 25 | Side effect (marznode update) without exception handling around the loop | One failing user kills the whole batch | `app/routes/service.py:113-118` |
| 26 | Per-endpoint `tags=[...]` instead of per-router | Tags are declared on the router once | `app/routes/service.py:15` |
| 27 | Adding CLI subcommands without registering them in `marzneshin-cli.py` | Subcommand is unreachable | `marzneshin-cli.py:13-15` |

## Decision Cheatsheet

- **Need to add a column?** → Alembic migration + extend `app/db/models.py` + extend `app/models/<feature>.py` + extend CRUD + update `__all__` + (rarely) extend route.
- **Need to add an endpoint?** → Add to `app/routes/<feature>.py`. If it's a brand-new resource, also create the schema + CRUD + model.
- **Need to send a notification on state change?** → Add enum entry + subclass in `app/models/notification.py`, fire via `asyncio.ensure_future(notify(...))` in the route.
- **Need to push to marznode?** → Import `from app import marznode`, call `marznode.operations.update_user(...)` inside a loop after the CRUD call. Reference: `app/routes/service.py:113-118`.
- **Need a periodic job?** → Add a module under `app/tasks/`, register it in `app/marzneshin.py:80-106`.
- **Need a row-as-dependency with auto 404?** → Add `get_<x>(id, db)` + `<X>Dep` alias to `app/dependencies.py`.
- **Need CLI exposure?** → New `cli/<feature>.py` with Typer subapp, register in `marzneshin-cli.py`.
